# AI 驱动学习与交付：通用约定

版本：v3，2026-10-30。替代旧版“亲手补 TODO”练习，不是补充作业。
目标：借助 Codex 或 Claude Code 快速理解陌生领域、实现需要的功能，并由用户对范围、关键决策、证据和风险边界负责。代码、测试、脚本和文档都可以交给 AI。

## 每周的边界
每周只交付一个可观察的最小功能，训练一项 AI 协作能力，并回答一个风险判断问题。一般按 120 分钟用户主动投入规划，另有 60 分钟可选深入；这不是所有安装、云构建与模型执行的完成时限。
建议分配：15 分钟理解目标，20 分钟评审方案，45 分钟驱动实现，25 分钟验收，15 分钟责任说明。
默认一个主执行会话，另开只读审查会话；不要求两个付费工具，不让多个会话同时改同一份代码。

AI 可以在已批准范围内持续编码、测试和修复。涉及新费用、外部资源、扩大权限、破坏性操作、生产系统、明显架构或范围变更时才停下请用户决定。不得擅自提交到远端、发布服务或购买产品。
不要让模型获得生产目录、生产数据库、生产凭证或不必要的主机权限。仅使用合成数据。环境阻塞约 20 分钟就报告原因和可行的缩小路线，不用 mock 冒充真实基础设施能力。

## 先验收规范，再实现
预期来自用户确认的规格、独立 fixture 或官方语义，不来自待测代码。
至少包含正常、边界/故障和用户自己选择的新输入。固定输入可重复运行；在可能存在随机性的回答中检查事实/行为，而不锁死措辞。
不能为让测试通过而删除/弱化规范。变更需求先确认并留下差异。
未执行不等于通过；环境不支持、缺少模型/账号/权限时明确阻塞。测试通过不代表生产可用。

## 最少交付
一份可运行结果；一份简短 DELIVERY.md 指向原始证据；用户自己的三句话判断。
DELIVERY.md 至少包括源码/依赖版本、启动与复现命令、关键 diff、实际输出与退出码、通过/失败/未执行测试、限制、停止/回滚/数据恢复方法。不要创建大量汇报文档。
用户回答：为什么接受方案；哪些证据支持接受结果；不能承诺什么、失败如何止损。
