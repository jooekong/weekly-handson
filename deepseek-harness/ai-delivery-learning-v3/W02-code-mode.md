# W02｜Code Mode：订单与优惠券排查的两种编排

计划周：2026-11-09 至 2026-11-15（北京时间）。
计划学习包：周一 2026-11-09 08:00 左右；工作日提醒：周四 2026-11-12 09:00 左右。
不要求前面所有周次已经完成；需要复用环境时也必须提供独立起步方案。

## 交付目标
让 AI 为同一组模拟订单、用户、优惠券、站点查询实现逐轮工具调用和代码编排两条路径，用同一测试集比较正确性和开销。

## 本周 AI 协作能力
将任务拆成依赖关系；用对照试验判断方案，而不默认代码编排更快更省。

## 只需掌握的核心知识
数据依赖与并行；工具编排；失败传播；相同任务的对照；端到端成本。解释必须围绕下列具体输入和关键决定，不做概念堆砌。

## 数据与测试前提
准备 6 个固定案例：可用、已过期、金额不足、站点不支持、缺失数据、工具超时。判定表先于实现冻结。独立查询允许并行，依赖字段要等待。

## 实现前固定的验收条件
| 序号 | 输入／操作 | 预期与观察方法 |
|---|---|---|
| 1 | 两条路径运行同一案例集 | 业务结论与判定表一致，错误与缺失数据不被当成业务拒绝。 |
| 2 | 某个查询超时 | 保留未知状态与失败来源，不编造原因；记录重试与部分结果。 |
| 3 | 重复运行并分开冷/热条件 | 记录模型往返、工具调用数、端到端耗时和可见用量；不可见费用标未知。 |

## 需要你作出的决定
哪些步骤可并行；失败后是否保留部分结果；是否值得采用更复杂的编排方式。

## 最少交付证据
两条执行轨迹、固定判定表、原始测量记录、环境和模型版本、结果差异与限制。 统一汇总到 DELIVERY.md 并链接原始结果，不以 AI 的成功总结替代。

## 你必须能回答的问题
更少模型往返是否真的带来更好的端到端效果？多步判断中哪里不能提前执行？

## 非目标
不接生产接口，不构建通用编排平台，不让未受控生成代码任意访问主机。

## 用户选择的变更／复测
用户改变一个工具延迟或业务约束，重新验证结论，不只重跑原始成功案例。

## 资料核验任务
核验所选 Code Mode 的官方设计与执行接口、所用模型/工具调用协议；对照方案必须具有相同任务范围。
本卡已生成的是任务规格，不是已运行结果。定时发送前需核验并补充 3—5 个可访问的官方资料入口、具体章节及版本/命令，不能编造引用或把今天的假定当未来事实。
